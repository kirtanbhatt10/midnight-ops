# NIST SP 800-115 — Technical Assessment (checklist)

Planning checklist aligned to [NIST SP 800-115, *Technical Guide to Information Security
Testing and Assessment*](https://csrc.nist.gov/pubs/sp/800/115/final). Use it to structure
network/host assessments. Items are planning and documentation steps; the operator
executes all technical activity against **in-scope** systems.

> Prerequisite: authorization + scope confirmed (`templates/rules-of-engagement.md`).

## Phase 1 — Planning
- [ ] Assessment objectives and type (review / target identification / validation) agreed
- [ ] Rules of engagement, constraints, and logistics documented
- [ ] Data-handling and confidentiality requirements agreed
- [ ] Roles, contacts, and escalation path recorded

## Phase 2 — Discovery
- [ ] In-scope ranges and hosts confirmed before any activity
- [ ] Network and host discovery *plan* recorded (what, when, from where)
- [ ] Service and version inventory captured as the operator runs it
- [ ] Findings staged for validation; nothing pursued outside scope

## Phase 3 — Attack / validation (operator-executed)
> The assistant records and organizes; it does not supply exploit code or commands.
- [ ] Candidate issues validated per the agreed validation plan
- [ ] Each action logged with time, source, target, and result
- [ ] Impact and reachable assets documented
- [ ] Stop-work triggers honored; incidents escalated per ROE

## Phase 4 — Reporting
- [ ] Results consolidated into finding records
- [ ] Severity assigned (CVSS) with business impact
- [ ] Remediation and mitigation guidance written
- [ ] Report assembled (`templates/report-template.md`) and classified appropriately

## Assessment techniques (coverage map)
Document which were **in scope** and used:
- [ ] Review techniques (documentation, log, ruleset, config review)
- [ ] Target identification & analysis (discovery, service identification, vuln scanning)
- [ ] Target vulnerability validation (operator-executed, authorized)

## Safeguards
- [ ] Testing scheduled to minimize operational impact
- [ ] Backups / rollback confirmed by the owner before invasive steps
- [ ] Sensitive data encountered handled per ROE and law
